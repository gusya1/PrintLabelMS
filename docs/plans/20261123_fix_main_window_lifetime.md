# План: окно закрывается сразу после загрузки — удержать MainWindow на время app.exec()

Источник: баг-репорт — на Linux в новой версии (0.4.0) после загрузки
главного окна приложение сразу закрывается, без ошибок и сообщений.

## Проблема

`_run_gui()` (`src/PrintLabelMS/__main__.py`) создаёт `MainWindow` внутри
слота `on_loaded()`, подключённого к `StartupLoader.loaded`. Окно живёт
только в локальной переменной функции-слота:

```python
def on_loaded(bundle):
    ...
    window = MainWindow(...)
    window.show()
    ...
    splash.finish(window)
loader.loaded.connect(on_loaded)
return app.exec() or exit_code
```

У `MainWindow` нет parent'а, поэтому единственный владелец C++ объекта —
Python-обёртка. Когда `on_loaded` возвращает управление, счётчик ссылок
падает до нуля, PyQt удаляет окно, срабатывает `quitOnLastWindowClosed`,
`app.quit()` завершает цикл событий и `app.exec()` возвращает 0. Снаружи
это выглядит как «окно открылось и сразу закрылось без ошибок» (код
возврата 0, исключения нет, в лог ничего не пишется).

До выноса загрузки в `StartupLoader` (`docs/plans/20261123_splash_immediate_show.md`,
коммит `b03b484`) окно создавалось в самой `_run_gui` и жило ровно
столько же, сколько цикл событий, — регрессия появилась вместе с
асинхронным стартом в 0.4.0. Проблема платформонезависима.

Воспроизведено локально (PyQt5 5.15.11, Windows): окно, созданное
внутри слота без внешней ссылки, удаляется сразу после возврата из слота,
проверка «живо ли окно» уже не выполняется — `app.quit()` происходит
раньше, `app.exec()` возвращает 0.

## Решение

1. `src/PrintLabelMS/__main__.py`, `_run_gui()`: завести контейнер владения
   до определения слотов (`refs = {"window": None}`) и в `on_loaded`
   сохранять в него окно (`nonlocal` не нужен — мутация словаря):
   `refs["window"] = window` перед `window.show()`. Контейнер остаётся
   локальной переменной `_run_gui`, а значит живёт весь `app.exec()`.
   Комментарий: окно обязано переживать возврат из слота, иначе PyQt
   удаляет его и приложение завершается.
2. Проверить остальные объекты из слота: `print_handler` и `converter`
   живы, т.к. `MainWindow` хранит `print_handler`, а `PrintHandler` —
   `converter`; `splash` — локальная переменная `_run_gui`. Правок
   не требуют.
3. Регресс-тест (см. ниже) на контракт «окно, созданное по сигналу
   загрузчика, живо во время `app.exec()`».

## Файлы для модификации

- `src/PrintLabelMS/__main__.py`: `_run_gui()` — контейнер `refs`
  и сохранение окна в нём в `on_loaded`.

## Файлы для создания

- `tests/test_gui_lifetime.py`: регресс-тест на удержание окна.
  Фикстура `qapp` — как в `tests/test_splash_screen.py`
  (`QT_QPA_PLATFORM=offscreen`). Тест вызывает `_run_gui()` с подменой:
  - `PrintLabelMS.startup_loader.StartupLoader` — QObject-заглушка
    с сигналами `loaded(object)`/`error(str)`, `start()` сразу эмитит
    `loaded` (кадр слота умирает после возврата из `emit` — то же
    условие, что и в реальном старте);
  - `gui.MainWindow.MainWindow` — заглушка-`QWidget`, записывающая
    `weakref.ref` на себя; принимает аргументы реального конструктора;
  - `PrintLabelMS.print_handler.PrintHandler` и
    `pdf_to_image_converter.converter.Converter` — заглушки;
  - `gui.message_box.fatal_error` — заглушка, чтобы не открывались
    модальные диалоги;
  - `QtWidgets.QApplication.exec` — заглушка, которая прокачивает
    `processEvents()` и проверяет, что окно из `weakref` ещё живо,
    затем возвращает 0.
  Бандл загрузчика — `SimpleNamespace`-конфиг (`ui_scale=1.0`,
  `printer.name`, `printer.resolution`, `label_formats=[]`,
  `check_updates=False`) плюс заглушки manager/assortment/templates/
  organization.

  Ассерт: к моменту работы «exec» окно не удалено (weakref возвращает
  объект). Без правки п. 1 тест падает, с правкой — проходит.

## Проверка

1) `pytest`; 2) `ruff check .`.
Дополнительно: ручной запуск на Linux установленной версии — окно
остаётся открытым после загрузки ассортимента.

## Актуализация документации

- `docs/gui.md`, раздел «Сплэш-экран»/«Главное окно»: окно создаётся по
  сигналу `StartupLoader.loaded` и удерживается владельцем до конца
  `app.exec()`; удаление окна (потеря ссылки) завершает приложение.
- `docs/architecture.md`, пункт 2 «Поток данных»: в описании старта
  указать, что `MainWindow` создаётся на главном потоке по сигналу
  загрузчика и живёт до завершения цикла событий.
