## 🔴 Критический баг

### B1. Неверная конвертация смещений этикетки (мм → пиксели)

**Где:** `src/PrintLabelMS/print_handler.py:35,38`

```python
self.__width_offset = int(width_offset * self.__resolution / 1000)
self.__height_offset = int(height_offset * self.__resolution / 1000)
```

**Суть:** деление на 1000 соответствует «точкам на метр», а разрешение задано
в DPI. Правильно — делить на 25.4 (мм в дюйме).

**Доказательство:** painter-координаты QPrinter — это device-пиксели при
заданном `setResolution`. Проверка offscreen: для страницы 58×40 мм при
600 DPI `pageRect()` = 1367×942, что совпадает с `мм * 600 / 25.4`
(1370×945 с учётом округления Qt), а не с `мм * 600 / 1000`.

**Влияние:** смещение 5 мм при 600 DPI даёт 3 пикселя вместо ~118, т.е.
настроенные смещения (компенсация подачи этикетки) фактически игнорируются.
В `settings_example.json` все смещения равны 0, поэтому дефект не проявлялся.

**Исправление:** `/ 25.4` вместо `/ 1000`.

## 🟠 Высокие (функциональные/UX)

### B2. Прогресс-диалог не закрывается при ошибке печати

**Где:** `src/gui/MainWindow.py:68-82,101-106`

`QProgressDialog(0..3, autoClose=True)` закрывается только при значении,
равном максимуму (3, «Готово»), а «Готово» эмитится **только при успехе**.
При сбое значение остаётся 1–2: диалог «Печать...» висит до ручного закрытия,
а `thread.join()` не достигается. QMessageBox с ошибкой показывается внутри
локального event loop `exec_()`; после его закрытия пользователь остаётся
с зависшим прогресс-баром.

**Исправление:** закрывать диалог на всех путях (эмитить максимум/закрывать
из слота ошибки), либо отказываться от `exec_()` в пользу сигналов.

### B3. Сплэш-экран не обновляется во время загрузки

**Где:** `src/PrintLabelMS/__main__.py:33-55`

После `splash.show()` идут блокирующие сетевые вызовы (ассортимент, шаблоны,
организации) без единого `processEvents()`. Сообщение «Загружаем товары...»
не перерисовывается: пользователь видит замороженный или пустой сплэш на всё
время загрузки.

**Исправление:** `processEvents()` после `showMessage()` и между шагами
загрузки (или перенос загрузки в воркер с обновлением через сигналы).

### B4. Нет таймаутов сети и отмены печати

**Где:** `src/PrintLabelMS/__main__.py`, `src/gui/MainWindow.py:101-106`,
MSApi `MSLowApi._create_session` (без `timeout`)

Сессия MSApi создаётся без таймаута (requests-дефолт — бесконечность),
приложение не передаёт `timeout` в `request_label`. Повисшее соединение даёт
вечный «Печать...»: у QProgressDialog нет кнопки отмены, `thread.join()` без
таймаута блокирует GUI.

**Исправление:** передавать `timeout` в вызовы MSApi, добавить отмену
(кнопка + флаг отмены в воркере), `join(timeout)`.

### B5. QPrinter/QPainter используются из фонового потока

**Где:** `src/gui/MainWindow.py:68-76` → `print_handler.reset_print_settings`,
`print_pdf`

Воркер мутирует QPrinter и рисует QPainter вне GUI-потока. Qt не
документирует QPrinter как thread-safe; на части платформ это UB.
Предыдущий план (C1, 2026-11-20) декларировал «воркер не трогает UI-состояние»,
но PrintHandler воркер трогает.

**Исправление:** все настройки принтера выполнять в GUI-потоке до старта
воркера; в воркере оставить только сеть/конвертацию/печать без мутации
разделяемого состояния (либо сериализовать доступ).

## 🟡 Средние

### B6. Тихий выбор первой организации

**Где:** `src/PrintLabelMS/__main__.py:47-50`

`organizations[0]` — при нескольких юрлицах этикетки печатаются от
произвольной (первой) организации: риск чужих цен/реквизитов на этикетке.

**Исправление:** минимум — предупреждение при `len > 1`; лучше — выбор
организации в UI.

### B7. Неполный перехват исключений при запуске

**Где:** `src/PrintLabelMS/__main__.py:57-66`

Ловятся только `MSApiException`, `RequestException`, `ValidationError`,
`OSError`, `RuntimeError`. Например `JSONDecodeError` из некорректного ответа
API или `AttributeError` внутри MSApi дают сырой traceback вместо диалога.

**Исправление:** catch-all `except Exception` → `fatal_error` (+ лог).

### B8. Печать без шаблона падает с непонятной ошибкой

**Где:** `src/gui/MainWindow.py:56-66`

Проверяется `label_format is None`, но **не проверяется `template`**.
Если у аккаунта нет кастомных шаблонов, combo пуст, `currentData()` = None,
и в воркере возникает `AttributeError: 'NoneType' object has no attribute
'get_meta'`.

**Исправление:** явная проверка с сообщением «Шаблон этикетки не выбран»
(и, при необходимости, «Шаблоны не найдены» при старте).

### B9. Ограничение «нужна цена продажи» не surfaced в UI

**Где:** MSApi `RequestLabelMixin.request_label`

Печать требует ≥1 цены продажи у товара, иначе
`MSApiException("Sale prices is empty in ...")`. Товары без цены продажи
напечатать нельзя — пользователь получает сырое сообщение библиотеки.

**Исправление:** понятный текст ошибки; по возможности — предпроверка или
подсказка в UI.

### B10. Нет логирования

В приложении не настроено логирование: ошибки живут только в диалогах и
теряются после закрытия, диагностика прошлых сбоев невозможна. MSApi пишет
`logging.debug`, но обработчики не сконфигурированы.

**Исправление:** файловый лог (хотя бы фатальные и операционные ошибки).

### B11. `print_pdf` теряет цепочку исключений и может не закрыть QPainter

**Где:** `src/PrintLabelMS/print_handler.py:49-65`

`except ConvertError as e: raise RuntimeError(str(e))` — без `from e`;
при исключении между `painter.begin()` и `painter.end()` painter остаётся
открытым.

**Исправление:** `raise ... from e` и `try/finally` вокруг painter.

## Мёртвый код

### D1. `src/PrintLabelMS/exceptions.py` не используется

`AppError` и `MoySkladError` не встречаются ни в одном файле проекта
(проверено grep). Файл можно удалить (или начать реально использовать
в обработке ошибок).

### D2. Пустой `src/__init__.py` при flat-раскладке пакетов

`src` не является пакетом: hatchling собирает подпакеты `src/*` как
top-level модули. Файл лишний.

### D3. `src/resources/resources/pictures/icon.ico` не используется

Ни код, ни формы на него не ссылаются (иконка окна — `icon.png`).
Мёртвый ресурс.

### D4. `import config` в `print_handler.py` только для аннотаций

`config` импортируется ради `config.Orientation` в сигнатуре; можно
`from __future__ import annotations` + `TYPE_CHECKING`. Мелочь.

## Архитектурные решения

### A1. Плоские top-level пакеты с общими именами

Из `src/` устанавливаются как отдельные top-level модули: `config`, `gui`,
`resources`, `moy_sklad`, `pdf_to_image_converter` плюс mixed-case
`PrintLabelMS`. Имена `config`/`gui`/`resources` очень общие — риск
shadowing при установке рядом с другими пакетами. Для публичного репозитория
чище единый namespace (например, `printlabelms.*`).

### A2. Хрупкая связь «row списка → индекс в ассортименте»

**Где:** `src/gui/MainWindow.py:60`

Combo-боксы хранят объекты через userData (`currentData()`), а список товаров
мапит `listProducts.row(item)` в индекс `self.__assortment`. Работает, пока
items не удаляются и не переупорядочиваются (фильтр только скрывает).
Последовательно — хранить product в data item, как в combo.

### A3. Пропуски валидации конфигурации

**Где:** `src/config/__init__.py:24-28`

`label_formats` без `min_length=1`: пустой список проходит валидацию и падает
только при печати. `moy_sklad_token` не проверяется на непустоту.
Fail-fast в pydantic дешевле.

### A4. `get_organizations()` грузит все организации ради `[0]`

**Где:** `src/moy_sklad/__init__.py:12-13`

MSApi поддерживает `limit`; можно `gen_list(limit=1)` (по духу исправления
N+1 при старте).

### A5. Хрупкий `test_build.py`

**Где:** `tests/test_build.py`, `src/gui/__build__.py:21`

`UI_FORM_LIST` вычисляется из реального каталога при импорте модуля;
monkeypatch `get_build_directory` перенаправляет только вывод. Тест
компилирует реальную `mainwindow.ui` в `tmp_path` — работает, но связан
с состоянием репозитория.

### A6. Двойная конвертация PDF → PPM → JPEG

**Где:** `src/pdf_to_image_converter/converter.py:15-20`

pdf2image рендерит PPM в память, затем Pillow перекодирует в JPEG
(quality 75). Можно сразу `fmt="jpeg"` (+ `grayscale`) у pdftoppm — быстрее
и лучше для термопечати.

### A7. Мелочи

- `license = { text = "MIT" }` в `pyproject.toml` — deprecated-форма
  PEP 639 (рекомендуется SPDX-строка).
- `fatal_error(e)` принимает exception там, где по имени ожидается message.
- `app.exit(1); exit()` — site-builtin вместо `sys.exit`.
